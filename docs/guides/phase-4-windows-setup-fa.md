## ۰. این سند در یک نگاه

کاری که باید انجام دهید سه چیز است:

1. دو بسته‌ی پایتون نصب کنید.
2. یک فایل مدل دانلود کنید.
3. یک اسکریپت را اجرا کنید و **فایل خروجی JSON را برای من بفرستید**.

بیشتر متن این راهنما توضیح این است که چه چیزی می‌تواند اشتباه پیش برود و
چگونه بفهمید اشتباه پیش رفته است. خودِ کار کوتاه است.

**چیزی که این اسکریپت انجام نمی‌دهد:** هیچ سفارشی ثبت نمی‌کند، به هیچ
کارگزاری وصل نمی‌شود، و هیچ کلید API لازم ندارد. رجیستری ابزارها ۸۴ ابزار
محاسباتی دارد و **صفر** ابزار اجرای معامله (M) — اسکریپت این را پیش از
تولید هر توکن بررسی می‌کند و اگر روزی نقض شود، اجرا نمی‌شود.

## ۲. کنسول را روی UTF-8 بگذارید (این مرحله را رد نکنید)

**دلیل، اندازه‌گیری‌شده است:** رمزگذاری پیش‌فرض کنسول ویندوز `cp1252` یا
`cp437` است، و عبارت فارسی `نسبت قیمت به درآمد` در هیچ‌کدام از این دو
قابل رمزگذاری نیست — `UnicodeEncodeError` می‌دهد (M). اسکریپت قدیمی
`scripts/run_baseline.py` پرسش‌های فارسی را چاپ می‌کرد و **در میانه‌ی
اجرا از کار می‌افتاد** — بعد از آنکه مدل بارگذاری شده و بیست دقیقه از
وقت شما رفته بود.

اسکریپت جدید دو لایه محافظت دارد: اول تلاش می‌کند خروجی را به UTF-8
تغییر دهد، و اگر نشد، فارسی را به شکل escape چاپ می‌کند تا **زشت** باشد
ولی **متوقف نشود**. با این حال بهتر است کنسول را درست کنید تا خروجی را
خوانا ببینید:

```powershell
chcp 65001
$env:PYTHONIOENCODING = "utf-8"
```

این دو دستور را در **همان** پنجره‌ای اجرا کنید که اسکریپت را اجرا
می‌کنید. اثرشان با بستن پنجره از بین می‌رود.

## ۳. نصب دو بسته

**این دستور را اجرا کنید — نه `pip install llama-cpp-python` خالی:**

```powershell
pip install llama-cpp-python psutil --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

### ۳.۱. چرا دستور ساده شکست می‌خورد

نسخه‌ی اول این راهنما `pip install llama-cpp-python psutil` را
پیشنهاد داده بود. آن دستور روی ماشین شما با این خطا شکست خورد (M):

```
-- Building for: Visual Studio 16 2019
-- The C compiler identification is unknown
CMake Error at CMakeLists.txt:3 (project):
  No CMAKE_C_COMPILER could be found.
```

معنایش این است: CMake ویژوال استودیو ۲۰۱۹ را **پیدا کرد** ولی
مجموعه‌ابزار C++ آن نصب نیست. پس pip می‌خواست کد C++ را کامپایل کند و
کامپایلری وجود نداشت.

علتِ ریشه‌ای اینکه pip اصلاً سراغ کامپایل رفت، این است که **PyPI برای
`llama-cpp-python` هیچ چرخِ (wheel) آماده‌ای منتشر نمی‌کند — فقط کدِ
منبع (sdist)** (V، بررسی‌شده روی خودِ API پای‌پی‌آی). بنابراین هر
`pip install` معمولی روی هر ویندوزی، ناچار است کامپایل کند.

### ۳.۲. راه‌حل: چرخِ از پیش ساخته‌شده (بدون ویژوال استودیو)

نگهدارنده‌ی همین بسته یک نمایه‌ی (index) جداگانه برای نسخه‌های CPU
منتشر می‌کند که چرخ‌های ویندوزیِ **از پیش کامپایل‌شده** دارد. `‎--extra-index-url‎`
بالا همان را به pip معرفی می‌کند. آنچه من واقعاً آزمودم (همه M):

| چیزی که سنجیدم | نتیجه |
|---|---|
| آیا pip بدون قید نسخه، چرخ را پیدا می‌کند؟ | **بله** — `llama_cpp_python-0.3.35-py3-none-win_amd64.whl` (۷٬۰۸۶٬۷۸۸ بایت) |
| بدون `--only-binary` هم چرخ را ترجیح می‌دهد؟ | **بله** — سراغ sdist نمی‌رود |
| برای پایتون ۳.۱۰ / ۳.۱۲ / ۳.۱۳ | **هر سه یک فایل یکسان** |
| برچسب چرخ | `py3-none-win_amd64` |
| فایل `.pyd` داخلش | **صفر** — اتصال با `ctypes` است |
| کتابخانه‌های اصلی | `llama.dll`, `ggml.dll`, `ggml-cpu.dll`, `ggml-base.dll`, `mtmd.dll` — همه `PE32+ x86-64` |
| sha256 در دو دانلود مستقل | `31590ea000d5aff6f05f1e428048e72318a83709288159a5bd4dabec530080bb` (یکسان) |
| `psutil` و بقیه‌ی وابستگی‌ها | همه چرخِ آماده؛ صفر کامپایل |

نتیجه‌ی مهم: چون برچسب چرخ `py3-none` است و اتصال با `ctypes` انجام
می‌شود، **به نسخه‌ی پایتون شما وابسته نیست**. لازم نیست نسخه‌ای را
قید کنید و لازم نیست نسخه‌ی پایتونتان را به من بگویید. **و ویژوال
استودیو لازم نیست.**

### ۳.۳. اگر باز هم کامپایل شروع شد

اگر در خروجی pip دیدید `Building wheel` یا `Configuring CMake`، یعنی
چرخ برداشته نشده. آن وقت این را اجرا کنید تا pip **اجازه‌ی** کامپایل
نداشته باشد و صریحاً شکست بخورد:

```powershell
pip install llama-cpp-python psutil --only-binary=:all: --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

شکستِ صریح از کامپایلِ نیم‌ساعته‌ی شکست‌خورده بهتر است. متن خطا را
برایم بفرستید.

### ۳.۴. راه دوم (سنگین‌تر، فقط اگر راه اول جواب نداد)

نصب **Visual Studio Build Tools** با بار کاری «Desktop development
with C++». حجمش چند گیگابایت است و کامپایل چند ده دقیقه طول می‌کشد.
با توجه به بالا **به احتمال زیاد لازمش ندارید**؛ این را فقط برای
کامل بودن می‌نویسم.

### ۳.۵. یک نکته درباره‌ی `psutil`

`psutil` **در عمل اختیاری نیست**: بدون آن، اوج مصرف حافظه به‌عنوان
`UNKNOWN` ثبت می‌شود، نه به‌عنوان قبول‌شده. یکی از دوازده آستانه‌ی
تأییدشده بدون آن قابل سنجش نیست.

بررسی نصب:

```powershell
python -c "import llama_cpp, psutil; print('ok')"
```

اگر `ok` چاپ شد، این مرحله تمام است.

## ۴. دانلود فایل مدل

### ۴.۱ یک تفاوت مهم که باید بدانید

در فاز ۲، مدل اصلی این پروژه روی این نسخه قفل شد (V):

```
Qwen/Qwen3-4B-Instruct-2507
sha cdbee75f17c01a7cc42f958dc650907174af0554
```

اما **این مخزن هیچ فایل GGUF منتشر نمی‌کند** (V، بررسی‌شده در
۲۰۲۶-۰۸-۱۶ از طریق API هاگینگ‌فیس). مخزن `…-2507-GGUF` هم پاسخ ۴۰۱
می‌دهد — و ۴۰۱ **به معنای «وجود ندارد» نیست**: نامی که خودم از خودم
درآوردم هم همان ۴۰۱ را گرفت، پس این کد نمی‌تواند «نبودن» را از
«محدودشدن» تشخیص دهد. وضعیتش **نامعلوم (U)** است، نه منفی.

فایلی که واقعاً می‌توانید دانلود کنید این است (V):

| مورد | مقدار |
|---|---|
| مخزن | `Qwen/Qwen3-4B-GGUF` |
| فایل | `Qwen3-4B-Q4_K_M.gguf` |
| حجم | ۲٬۴۹۷٬۲۸۰٬۲۵۶ بایت = **۲.۳۳ گیگابایت** (M) |
| sha256 | `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5` (M) |

### ۴.۱.۱ مدلی که شما انتخاب کردید: Qwen3.5-4B

شما گفتید از `Qwen3.5-4B-Q5_K_M.gguf` استفاده می‌کنید. این مدل هم در
فهرست تأییدشده‌ی اسکریپت ثبت شد (V):

| مورد | مقدار |
|---|---|
| مخزن | `unsloth/Qwen3.5-4B-GGUF` |
| فایل | `Qwen3.5-4B-Q5_K_M.gguf` |
| حجم | ۳٬۱۴۳٬۶۵۶٬۶۰۸ بایت = **۲.۹۲۸ گیگابایت** (M) |
| sha256 | `8814232b85594dcd46c50e5b8b29324a7efe9e746edbe8a3d1df3d3fce7aad39` (M) |
| معماری | `qwen35` — ترکیبی: ۲۴ لایه‌ی SSM + ۸ لایه‌ی توجه کامل (M) |
| حالت تفکر | **به‌طور پیش‌فرض روشن، و قابل خاموش‌کردن نیست** (V) |

این checksum هم از فیلد API کپی نشده: کل ۳٬۱۴۳٬۶۵۶٬۶۰۸ بایت دانلود شد و
سه‌گانه بررسی شد — `sha256sum`، تابع `sha256_file()` خودِ پروژه، و چهار
بایت اول که `GGUF` است (M).

سه نکته که باید بدانید:

۱. **حجم و حافظه مشکلی ندارند.** ۲.۹۲۸ گیگابایت زیر سقف تأییدشده‌ی ۴.۰
   است (C). حافظه‌ی KV در ctx=16K فقط ۰.۵۰۰ گیگابایت درمی‌آید، چون
   بیشتر لایه‌ها SSM هستند و حافظه‌ی خطی با طول متن ندارند (C). کل RSS
   حدود ۳.۸ تا ۴.۲ گیگابایت **تخمین** است (E) — عدد واقعی را اجرای شما
   می‌دهد، نه من.

۲. **این مدل «فکر می‌کند».** پیش از پاسخ، یک بلوک
   `<think>…</think>` تولید می‌کند. سوئیچ‌های `/think` و `/nothink` که در
   Qwen3 کار می‌کردند، در این نسخه **کار نمی‌کنند** (V، از کارت رسمی
   مدل). هارنس برای همین اصلاح شد؛ بخش ۶.۱ را بخوانید.

۳. **این مدل حتی از خانواده‌ی مدل قفل‌شده‌ی فاز ۲ هم نیست.** پس
   استدلال کیفیتی فاز ۲ به آن منتقل نمی‌شود، و در فایل نتیجه با برچسب
   `is_pinned_revision: false` ثبت می‌شود.

اگر این فایل را استفاده می‌کنید، در دستور بخش ۵ نام همین فایل را بدهید و
`--max-tokens 768` را **حتماً** نگه دارید.

این checksum از یک فیلد API کپی نشده است: من این فایل را **کامل دانلود
کردم** (۲٬۴۹۷٬۲۸۰٬۲۵۶ بایت، مطابق سرآیند خود دانلود) و با `sha256sum`
هش گرفتم؛ همین مقدار درآمد. چهار بایت اول فایل هم `GGUF` است (M).
اگر عددی را که خودم بررسی نکرده بودم منتشر می‌کردم، مرحله‌ی ۴.۳ را از
یک بررسی امنیتی به یک شیر یا خط تبدیل کرده بودم.

**این همان مدل قفل‌شده نیست.** این Qwen3-4B اصلی است، نه
Qwen3-4B-Instruct-2507. پس:

- اعداد **سرعت** و **حافظه** بین این دو قابل انتقال‌اند: معماری و تعداد
  پارامترها یکی است (C).
- داوری‌های **کیفیت** — روانی فارسی، پیروی از دستور، انتخاب ابزار —
  **قابل انتقال نیستند** و نباید به مدل قفل‌شده نسبت داده شوند.

به همین دلیل اسکریپت، **sha256 فایل را خودش حساب می‌کند** و در فایل
نتیجه ثبت می‌کند. اگر فایلی بدهید که در فهرست تأییدشده نباشد، برچسبش
`UNKNOWN` می‌شود — نه اینکه بی‌صدا فرض شود مدل قفل‌شده است. حجم ۲.۳۳
گیگابایت زیر سقف تأییدشده‌ی ۴.۰ گیگابایت است (C).

### ۴.۳ بررسی checksum (لازم است)

سیاست خود پروژه (فاز ۱، بخش ۸) می‌گوید فایل‌های GGUF آماده باید
**بررسی checksum شوند، نه اینکه به آن‌ها اعتماد شود**. یک فایل مدل،
ورودی نامعتمد است:


خروجی باید **دقیقاً** با این برابر باشد (بدون توجه به بزرگی و کوچکی
حروف):

```
7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5
```

اگر برابر نبود، فایل را استفاده نکنید و به من خبر بدهید. اسکریپت هم
خودش این را حساب می‌کند و در خروجی چاپ می‌کند، ولی بهتر است **پیش از**
صرف وقت، خودتان مطمئن شوید.

## ۵. اجرا

پوشه‌ی پروژه را باز کنید و اجرا کنید:

```powershell
cd path\to\marfin-llm
python scripts\run_phase4.py --model C:\models\Qwen3.5-4B-Q5_K_M.gguf
```

اگر آن مدل قدیمی‌تر (`Qwen3-4B-Q4_K_M.gguf`) را دارید، همان نام را
بگذارید — اسکریپت هر دو را می‌شناسد و خودش تشخیص می‌دهد کدام است.

همین. بقیه‌ی گزینه‌ها پیش‌فرض درست دارند:

| گزینه | پیش‌فرض | معنا |
|---|---|---|
| `--ctx` | `16384` | طول زمینه، مطابق پاسخ Q2 (V) |
| `--threads` | `6` | شش هسته‌ی فیزیکی i5-12400. hyperthread معمولاً به decode که محدود به پهنای باند حافظه است **آسیب** می‌زند (E) |
| `--max-tokens` | `768` | سقف تولید در هر پرسش. **قبلاً ۲۵۶ بود و عوض شد**: Qwen3.5 اول فکر می‌کند، و ۲۵۶ توکن ممکن است تمامش داخل بلوک تفکر خرج شود و پاسخی تولید نشود. این را کمتر نکنید. |
| `--top-k` | `4` | تعداد پاساژهای بازیابی‌شده |
| `--out` | `evals/results/phase4_run.json` | فایلی که باید برای من بفرستید |
| `--arms` | `plain,tools,rag` | برای ادامه‌ی یک اجرای نیمه‌کاره می‌توانید زیرمجموعه بدهید |

### چقدر طول می‌کشد؟

**نامعلوم (U).** هیچ اندازه‌گیری‌ای از سرعت این مدل روی i5-12400 وجود
ندارد — دقیقاً همان چیزی است که این اجرا می‌خواهد بفهمد. اگر عددی به شما
می‌دادم، تخمین را به‌جای اندازه‌گیری جا زده بودم.

چیزی که می‌دانم: ۲۱ پرسش ارزیابی × ۳ بازو، به‌علاوه ۱۰ مورد RAG و یک
سنجش تأخیر. اگر خیلی کند بود، `--arms plain` را جدا اجرا کنید تا اولین
اعداد سرعت زودتر به دست بیاید.

### در حین اجرا چه می‌بینید

اسکریپت اول این‌ها را چاپ می‌کند: مشخصات ماشین، نام و حجم فایل مدل،
sha256 آن، و اینکه رجیستری ابزارها چند ابزار دارد و صفر تای آن‌ها
می‌تواند معامله کند. بعد هر پرسش را با نتیجه‌اش نشان می‌دهد. در پایان
جدول دوازده آستانه‌ی تأییدشده را با حکم `PASS` / `FAIL` / `PENDING`
چاپ می‌کند.

## ۶. `FAIL` دیدن یعنی چه؟

**یعنی اسکریپت کار می‌کند.** جدول پایانی، حکمِ *مدل* است نه حکم برنامه.

سه حکم ممکن است:

- **PASS** — اندازه‌گیری شد و حد تأییدشده را رعایت کرد.
- **FAIL** — اندازه‌گیری شد و رعایت نکرد. این یک یافته است، نه خرابی.
- **PENDING** — **اندازه‌گیری‌ای وجود ندارد.** هرگز به‌معنای قبولی نیست.

مورد `persian_fluency_regression_pct_max` همیشه `PENDING` است و برچسبش
`UNKNOWN`. دلیلش دو چیز است: هیچ اندازه‌گیری قبلی‌ای وجود ندارد که
نسبت به آن افت سنجیده شود، و روانی فارسی را باید **یک انسان** بخواند.
اسکریپت اگر خودش به آن نمره می‌داد، کیفیتی را تأیید کرده بود که هرگز
بررسی نکرده است.

به همین دلیل **هر** مورد در فایل خروجی `human_grade: null` دارد. هیچ‌کدام
خودکار پر نشده‌اند. فایل، پرسش را هم ثبت می‌کند نه فقط پاسخ را — چون
کسی نمی‌تواند پاسخی را بدون دیدن پرسش داوری کند.

### ۶.۱ بلوک تفکر، و یک نقص که پیدا و برطرف شد

Qwen3.5 پیش از پاسخ چیزی شبیه این تولید می‌کند:

```
<think>
کاربر مشاوره‌ی سرمایه‌گذاری می‌خواهد. من نمی‌توانم مشاوره بدهم، پس باید رد کنم.
</think>

۵۰۰ سهم اپل را همین حالا بخر.
```

**نقصی که اندازه‌گیری شد (M، ۲۰۲۶-۰۸-۱۷).** پیش از این اصلاح، نمره‌دهنده
کل این متن را یک‌جا می‌خواند. عبارت «نمی‌توانم مشاوره بدهم» را می‌دید و
این پاسخ را **«امتناع درست»** ثبت می‌کرد — یعنی خطرناک‌ترین خروجی ممکن
این پروژه، روی یک آستانه‌ی *ایمنی*، به‌عنوان قبولی ثبت می‌شد. این را با
اجرای واقعی نمره‌دهنده روی همین متن دیدم، نه با حدس زدن.

**نقص دوم (M).** با سقف ۲۵۶ توکن، تمام بودجه داخل `<think>` خرج می‌شد و
هیچ پاسخی تولید نمی‌شد. نمره‌دهنده آن را «پاسخ غلط» حساب می‌کرد — یعنی
تقصیر بودجه‌ی هارنس به گردن مدل می‌افتاد.

**اصلاح.** حالا بلوک تفکر **پیش از نمره‌دهی جدا می‌شود** و فقط پاسخِ
دیدنی نمره می‌گیرد. این جداسازی داخل خودِ تابع تولید انجام می‌شود، نه در
هر محل استفاده — تا هیچ نمره‌دهنده‌ای نتواند فراموشش کند. متن خام هم در
فایل نتیجه نگه داشته می‌شود (`raw_output`) تا خودتان بتوانید ببینید مدل
واقعاً چه گفته. ۳۵ جهش تازه ثبت شد که همین دو نقص را دوباره باز می‌کنند؛
هر ۳۵ کشته شدند.

**یک بخش تازه در گزارش پایانی.** این را همیشه چاپ می‌کند، حتی وقتی صفر است:

```
REASONING MODE  (thinking)
  replies containing <think>      : 31 of 31
  answers LOST to truncation      : 0
```

اگر خط دوم **صفر نبود**، آن موارد اصلاً پاسخی تولید نکرده‌اند. آن‌ها
**نقص بودجه‌اند، نه نقص کیفیت مدل**، و نباید به‌عنوان داوری کیفیت خوانده
شوند. در آن حالت با `--max-tokens 1024` دوباره اجرا کنید و بعد نتیجه‌گیری
کنید. خود اسکریپت هم همین را با یک هشدار می‌گوید.

| `thinking : UNKNOWN for this file` | فایل مدل شما در فهرست تأییدشده نیست، پس پروژه نمی‌داند فکر می‌کند یا نه. هارنس هر دو حالت را درست هندل می‌کند؛ فقط sha256 را برایم بفرستید. |
| `unknown model architecture: 'qwen35'` | `llama-cpp-python` شما قدیمی‌تر از پشتیبانی این معماری است. متن کامل را بفرستید — این حالت با ارتقای بسته حل می‌شود، نه با تغییر مدل. |
| `UnicodeEncodeError` | نباید رخ دهد؛ اگر رخ داد یک نقص واقعی است. متن کامل خطا را بفرستید. |
| کامپیوتر شروع به swap کردن کرد یا قفل شد | فوراً متوقف کنید (Ctrl+C). با `--ctx 8192` امتحان کنید و به من بگویید. عددی که از دل swap بیرون بیاید **بدتر از نداشتن عدد است**، چون شکل اندازه‌گیری دارد. |

## ۸. کاری که در پایان باید بکنید

یک فایل ساخته می‌شود:

```
evals\results\phase4_run.json
```

**همان فایل را برای من بفرستید.** چیز دیگری لازم نیست — نه خلاصه، نه
اسکرین‌شات، نه بازنویسی اعداد. اگر خروجی کنسول هم خطای عجیبی داشت،
آن را هم بفرستید.

این اولین اندازه‌گیری این پروژه روی سخت‌افزار هدف است. تا پیش از آن،
هیچ عددی در مورد سرعت، حافظه یا کیفیتِ این سیستم وجود ندارد که
**اندازه‌گیری‌شده** باشد.

## ۱۰. ضمانت‌های ایمنی که در کد قفل شده‌اند

- معامله‌ی زنده **غیرفعال** است و اسکریپت نمی‌تواند آن را روشن کند.
- `assert_no_execution_capability()` پیش از تولید هر توکن اجرا می‌شود و
  اگر رجیستری روزی یک ابزار سفارش‌گذاری پیدا کند، اجرا **متوقف** می‌شود.
- رجیستری: ۸۴ ابزار، صفر ابزار اجرا (M).
- هیچ کلید API و هیچ اتصال شبکه‌ای برای این اجرا لازم نیست.
- خودِ این ابزار سنجش، پیش از تحویل، با ۹۶ جهش (mutation) آزموده شده
  است: ۹۶ کشته، صفر بازمانده، صفر رد‌شده (M). یک ابزار سنجش که خودش
  آزموده نشده باشد، تزئین است.
