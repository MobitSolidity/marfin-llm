# گام ۱ — اتصال به Google AI Studio (Gemini) با دستور دقیق CMD

**تاریخ نوشتن:** ۲۰۲۶-۰۸-۲۷
**مخاطب:** شما، روی ویندوز ۱۱، کاربر `moham`، پروژه در `C:\marfin-llm`
**پیش‌فرض:** هیچ چیز نصب‌شده‌ای لازم نیست جز آنچه در راهنمای فاز ۴ نصب کردید

---

## ۰. چرا Google AI Studio برای گام ۱ انتخاب شد

سه دلیل، و هر سه قابل بررسی:

1. **لایه‌ی رایگانِ مستند دارد.** در پروژه، `free_tier` برای `google` مقدار
   `True` دارد. یعنی نگهبان هزینه بدون `--allow-paid` جلوی اجرا را
   نمی‌گیرد. شما گفتید «رده‌ی رایگان، هیچ هزینه‌ای نکن» — این با آن سازگار
   است.
2. **کلید گرفتن از آن کارت بانکی نمی‌خواهد.** برای گرفتن کلید فقط یک حساب
   گوگل لازم است.
3. **گویش سیم آن جداگانه پیاده شده است.** در پروژه `wire` برای گوگل مقدار
   `google` است، نه `openai`. یعنی مسیر کد آن آزمون‌شده و اختصاصی است.

**آنچه انتخاب نشد و چرا:** `groq` و `cerebras` هم لایه‌ی رایگان مستند
دارند، اما شما گفتید «برای گام ۱ دستور google studio را بنویس». همین کافی
است. دو مورد دیگر هر وقت خواستید با همین الگو کار می‌کنند؛ فقط نام
ارائه‌دهنده و نام متغیر عوض می‌شود.

---

## ۱. صادقانه‌ترین چیزی که باید پیش از شروع بدانید

این سه جمله را با هم بخوانید، چون با هم معنا می‌دهند:

- **سهمیه‌ی رایگان گوگل در این پروژه ثبت نشده است.** روز ۲۰۲۶-۰۸-۲۷ که
  جست‌وجو کردم، اعداد منتشرشده برای همین یک ارائه‌دهنده **با هم متناقض**
  بودند. پس در کد نوشته شده: لایه‌ی رایگان `مستند`، سهمیه `UNKNOWN`.
  عددی که ندانم را نمی‌نویسم.
  اگر عدد امروز را می‌خواهید، منبع خودِ گوگل است:
  <https://ai.google.dev/gemini-api/docs/rate-limits>
- **«لایه‌ی رایگان» یعنی ممکن است به سقف بخورید، نه اینکه هرگز پول ندهید.**
  اگر حسابتان را به صورت‌حساب وصل کرده باشید، عبور از سقف می‌تواند هزینه
  بسازد. این تصمیم دست شما و در حساب گوگل شماست، نه در این کد.
- **اجرای API نمی‌تواند شکست سخت‌افزار را جبران کند.** این مهم‌ترین جمله‌ی
  این سند است و در بخش ۶ توضیح داده شده.

---

## ۲. گرفتن کلید — گام به گام

۱. به این نشانی بروید: <https://aistudio.google.com/app/apikey>
۲. با حساب گوگل وارد شوید.
۳. دکمه‌ی **Create API key** را بزنید.
۴. کلید ساخته‌شده را کپی کنید. شکل آن چیزی شبیه `AIzaSy...` است و حدوداً
   ۳۹ نویسه دارد.

**هشدار، پیش از گام بعد:**

- کلید را در هیچ فایلی از این پروژه **نچسبانید**. نه در کد، نه در
  `PROJECT_STATE.json`، نه در یادداشت. کد این پروژه کلید را **فقط** از
  متغیر محیطی می‌خواند و هرگز چاپ نمی‌کند.
- کلید را برای من (یا هر عامل دیگری) **نفرستید**. لازم نیست. من فقط دستور
  را می‌نویسم؛ کلید در ماشین شما می‌ماند.
- اگر کلید جایی لو رفت، از همان صفحه‌ی بالا حذفش کنید و کلید نو بسازید.

## ۳. دستور CMD — نسخه‌ی موقت (فقط همین پنجره)

این ساده‌ترین و **کم‌خطرترین** راه است: کلید فقط تا وقتی این پنجره‌ی CMD
باز است وجود دارد و با بستن پنجره از بین می‌رود.

```cmd
cd C:\marfin-llm
chcp 65001
set GEMINI_API_KEY=کلیدی-که-کپی-کردید
python scripts\panel.py --check google
```

توضیح هر خط:

| خط | کار |
|---|---|
| `cd C:\marfin-llm` | رفتن به پوشه‌ی پروژه |
| `chcp 65001` | UTF-8 کردن کنسول تا فارسی و جدول‌ها درست دیده شوند |
| `set GEMINI_API_KEY=...` | گذاشتن کلید **فقط در همین پنجره** |
| `python scripts\panel.py --check google` | بررسی آمادگی، **بدون تماس شبکه** |

**دو نکته‌ی ریز که مردم را زمین می‌زند:**

- در `set` دور مقدار **کوتیشن نگذارید**. ویندوز کوتیشن را بخشی از مقدار
  حساب می‌کند و کلید غلط می‌شود.
- دور `=` **فاصله نگذارید**. `set GEMINI_API_KEY = abc` متغیری با نام
  `GEMINI_API_KEY ` (با فاصله در آخر) می‌سازد که هیچ‌وقت خوانده نمی‌شود.

خروجی موفق شامل این دو سطر است:

```
  key state        set (39 chars)
  usable now       YES
```

اگر `NOT SET` دیدید، یعنی `set` نگرفته است — پنجره را نبسته‌اید؟ همان
پنجره باید باشد.

## ۴. دستور CMD — نسخه‌ی ماندگار (اختیاری)

اگر می‌خواهید هر بار مجبور نباشید `set` بزنید:

```cmd
setx GEMINI_API_KEY "کلیدی-که-کپی-کردید"
```

**تفاوت `set` و `setx`، و اینکه چرا این تفاوت اهمیت دارد:**

| | `set` | `setx` |
|---|---|---|
| دامنه | همین پنجره | همیشگی، برای کاربر `moham` |
| پنجره‌ی فعلی | فوراً اثر می‌کند | **اثر نمی‌کند** |
| کوتیشن | نباید بگذارید | **باید** بگذارید |
| ذخیره در | حافظه | رجیستری ویندوز |

**`setx` روی پنجره‌ی فعلی اثر نمی‌گذارد.** این پرتکرارترین سرگردانی است:
`setx` می‌زنید، پیام موفقیت می‌گیرید، بعد `--check` می‌گوید `NOT SET`.
هیچ چیز خراب نیست — باید **CMD را ببندید و پنجره‌ی نو باز کنید**.

**و یک هشدار جدی:** `setx` کلید را در رجیستری ویندوز می‌نویسد. اگر این
کامپیوتر مشترک است، هر کسی که با کاربر `moham` وارد شود کلید را دارد. روی
ماشین مشترک، `set` امن‌تر است.

برای پاک کردن دائمی بعداً:

```cmd
setx GEMINI_API_KEY ""
reg delete HKCU\Environment /F /V GEMINI_API_KEY
```

## ۵. اجرای فاز ۴ با Gemini

اول با کنسول تعاملی ببینید دستور دقیق چیست (این کنسول **هیچ اجرایی
نمی‌کند**، فقط دستور را نشان می‌دهد):

```cmd
cd C:\marfin-llm
python scripts\panel.py
```

بعد در کنسول تعاملی:

```
marfin> engine google
marfin> run
```

کنسول دستور را چاپ می‌کند و **می‌ایستد**. دستور اجرا این است:

```cmd
python scripts\run_phase4.py --provider google --model-id gemini-2.0-flash
```

**درباره‌ی `--model-id`، صادقانه:** `gemini-2.0-flash` در پروژه به عنوان
**راهنمای تأییدنشده** (`UNVERIFIED hint`) ثبت شده، نه واقعیت. نام مدل‌های
گوگل عوض می‌شود و من نمی‌توانم از این‌جا امروزِ شما را بررسی کنم. نام دقیق
مدل‌های در دسترس کلید خودتان را از اینجا ببینید:
<https://ai.google.dev/gemini-api/docs/models>

اگر نام غلط بدهید، خطای ارائه‌دهنده می‌گیرید — که بی‌خطر است، چون هیچ
محاسبه‌ای انجام نشده.

## ۶. مهم‌ترین بخش این سند — چه چیزی را حل می‌کند و چه چیزی را نه

اجرای Gemini **مسئله‌ی کندی CPU شما را حل می‌کند**، ولی **آستانه‌های
سخت‌افزاری را تعیین نمی‌کند**. این دو چیز جدا هستند.

وضعیت فعلی، که با اجرای واقعی روی ماشین شما اندازه‌گیری شده:

```
۸ ناموفق (FAIL) / ۳ موفق (PASS) / ۱ در انتظار (PENDING)  از ۱۲   [COMPUTED]
```

- سرعت مدل محلی **۳٫۶۲ تا ۴٫۳۸ توکن بر ثانیه** اندازه‌گیری شد
  (`MEASURED`)، در برابر کف تأییدشده‌ی **۸**. این یک شکست واقعی است.
- وقتی با API اجرا کنید، **چهار آستانه به `PENDING` می‌روند** و شاهد با
  برچسب `MEASURED_REMOTE_API` ثبت می‌شود.

**چرا این‌طور طراحی شده:** اگر اجرای ابری اجازه داشت آستانه‌ی سرعت را
«موفق» کند، شما در پایان یک گزارش سبز داشتید که درباره‌ی سخت‌افزار شما
هیچ نمی‌گفت. آن گزارش بدتر از نداشتنِ گزارش بود. سرعت GPU گوگل واقعیتی
درباره‌ی i5-12400 شما نیست.

**و این تغییر نمی‌کند:** `phase_4/measurements_recorded` هنوز `None`
است و باید `None` بماند. دروازه بسته است. معاملات زنده `False` است.

## ۷. اگر خطا گرفتید

| نشانه | معنا | کار |
|---|---|---|
| `key state: NOT SET` | متغیر خوانده نشد | با `set` در همین پنجره؛ با `setx` پنجره‌ی نو |
| `401` یا `403` | کلید نامعتبر یا حذف‌شده | کلید نو از صفحه‌ی AI Studio |
| `429` | به سهمیه خوردید | صبر، یا `groq` / `cerebras` را امتحان کنید |
| `404` روی نام مدل | `--model-id` غلط | فهرست مدل‌ها را ببینید (بخش ۵) |
| خروجی به‌هم‌ریخته | UTF-8 نشده | `chcp 65001`، یا `--ascii --no-colour` |
| `refusing plaintext http://` | نگهبان کد جلوی HTTP را گرفت | درست است؛ دست نزنید |

برای بررسی اینکه پروژه کلید را می‌بیند یا نه، **بدون** آنکه کلید چاپ شود:

```cmd
python scripts\panel.py --check google
```

این فرمان **طول** کلید را می‌گوید، هرگز مقدارش را. اگر طول عجیب بود
(مثلاً ۴۱ در حالی که باید ۳۹ باشد)، احتمالاً کوتیشن یا فاصله اضافه شده.
